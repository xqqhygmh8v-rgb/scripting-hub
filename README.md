# 📚 脚本中心（Scripting Hub）

一个全自动的脚本收集仓库，汇集 GitHub 上 **Scripting**、**Scriptable** 以及 **iOS 脚本** 相关的项目与脚本文件。
你不需要手动寻找，每隔一段时间它会自动更新。

---

## ✨ 这个仓库是做什么的

- 🔍 **自动搜索**：在 GitHub 上查找带有以下主题标签（topic）的公开仓库：
  - `scriptable`
  - `scripting`
  - `ios-scripting`
  - `scripting-app`
- 🇨🇳 **中文关键词搜索**：额外搜索「Scriptable 脚本」「签到脚本」等中文关键词，发现中文社区的项目。
- 📦 **自动下载**：对每个仓库，下载其最近 5 个 Release 中的资源文件（脚本、压缩包等）。
- 🗂️ **自动分类**：按照 `作者 / 仓库 / Release 版本` 的层级整理保存，并按类别分组。
- 📝 **中文目录**：更新 `index.json` 和 `CATALOG.md`。中文简介为基于词典的参考译文，原文简介会一并保留。
- 🧹 **自动清理**：每次同步都会检查已保存的内容，移除失效的仓库和文件（详见下文）。

## ⚙️ GitHub Actions 如何运行

工作流文件位于 `.github/workflows/sync.yml`，名称为 **「同步脚本中心」**。

| 触发方式 | 说明 |
|---|---|
| ⏰ 定时运行 | 每 6 小时运行一次（UTC 时间的整点） |
| 🖱️ 手动运行 | 在 Actions 页面手动触发（见下方说明） |

每次运行的步骤如下：

1. **拉取仓库代码**：获取最新的仓库内容。
2. **安装 Python 3.12**：准备运行环境。
3. **运行同步脚本**：执行 `sync.py`，搜索仓库、下载文件、清理失效内容。
4. **提交并推送变更**：如果有新内容或有内容被清理，就自动提交并推送到本仓库；如果没有变化，则跳过提交。

> 同一时间只会运行一个同步任务，避免多个任务同时修改仓库造成冲突。

## 🧹 自动检查与失效清理机制

每次同步结束后，`sync.py` 会检查 `scripts-store/` 中已保存的内容，并自动清理以下情况：

| 情况 | 处理方式 |
|---|---|
| 仓库在 GitHub 上已删除（返回 404） | 删除该仓库的本地目录 |
| 仓库已改为私有、已归档或已变为 Fork | 删除该仓库的本地目录 |
| 仓库不再符合搜索条件 | 删除该仓库的本地目录 |
| Release 已删除，或资源文件已从 Release 中移除 | 删除对应的旧文件 |
| 下载不完整的残留文件 | 删除，并在下次同步时重新下载 |
| 清理后留下的空目录 | 删除 |

为了避免误删，程序有以下保护规则：

- **搜索失败时跳过仓库级清理**：只要有任一搜索请求失败，本次就不删除任何仓库，避免临时故障造成大面积误删。
- **Release 获取失败时保留文件**：某个仓库的 Release 列表获取失败时，该仓库已有的文件会保留到下次同步。
- **状态无法确认时保留仓库**：查询仓库状态时如遇到非 404 错误（例如接口限流或网络问题），该仓库会被保留。

每次清理的内容都会记录在两个地方：

- `index.json` 中的 `pruned` 字段，包含时间、类型、对象和原因。
- `CATALOG.md` 末尾的「清理记录」表格。

运行日志中也会输出每一条清理动作。

## 📁 目录结构

```
scripting-hub/
├── sync.py                  # 同步脚本（搜索、下载、分类、清理、生成目录）
├── index.json               # 机器可读的索引（所有仓库、文件列表与清理记录）
├── CATALOG.md               # 人类可读的中文脚本目录（表格形式，含清理记录）
├── README.md                # 本说明文件
├── .github/
│   └── workflows/
│       └── sync.yml         # GitHub Actions 工作流配置
└── scripts-store/           # 下载的脚本文件（运行后生成）
    └── <作者>/
        └── <仓库名>/
            └── releases/
                └── <版本标签>/
                    └── <文件名>
```

各文件说明：

- **`sync.py`**：核心脚本，负责所有的同步与清理逻辑。
- **`index.json`**：包含每个仓库的名称、链接、中英文简介、类别、Star 数、来源、已下载文件列表，以及清理记录。
- **`CATALOG.md`**：按「中文相关 / 其他」和类别分组列出所有仓库，末尾附清理记录。
- **`scripts-store/`**：实际保存的脚本与资源文件，首次成功运行后才会出现。

## 🖱️ 如何手动触发同步

不想等待定时任务？可以随时手动运行：

1. 打开本仓库页面，点击顶部的 **Actions** 标签。
2. 在左侧列表中选择 **「同步脚本中心」**。
3. 点击右侧的 **Run workflow** 按钮。
4. 确认分支为 `main`，再次点击绿色的 **Run workflow** 即可开始。

运行完成后，刷新页面即可看到最新的 `CATALOG.md`、`index.json` 和 `scripts-store/` 内容。

### 在本地运行

```bash
python sync.py
```

建议设置环境变量 `GITHUB_TOKEN`，以避免 GitHub API 的速率限制：

```bash
export GITHUB_TOKEN=你的令牌
python sync.py
```

## ❓ 常见问题

- **为什么有些仓库没有出现？**
  只收录公开、非 Fork、未归档的仓库，并且每个主题或关键词最多取 30 个。
- **为什么有些文件没有下载？**
  只下载以下扩展名的文件：`.js`、`.ts`、`.tsx`、`.jsx`、`.zip`、`.scripting`、`.json`、`.md`；超过 25 MB 的文件也会跳过。
- **仓库被清理了怎么办？**
  清理只针对本地保存的副本，不会影响 GitHub 上的原仓库。如果仓库之后重新公开或符合条件，下次同步会自动重新收录。
- **脚本能直接使用吗？**
  每个仓库的版权和许可证归原作者所有。使用或二次分发前，请先查看原仓库的许可证说明。
